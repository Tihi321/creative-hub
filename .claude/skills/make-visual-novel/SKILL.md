# Make a visual novel

The hub is `C:\projects\Personal\creative-hub`. `README.md` there maps every repo, port and data folder; `services.json` is the machine-readable registry. Read the README once if anything below is unclear. For a short film, cartoon or video (not a visual novel) use the `make-video` skill.

## 0. Before you start

1. Run `pwsh -File scripts\hub.ps1` (status). Start what the run needs with `pwsh -File scripts\hub.ps1 start [ids]`. The default `start` brings up vn-studio, pixel-studio, chiptune-studio, book-translator, comfyui, comfy-mcp, lmstudio, vibetts. Scriptorium is never started by default: it resumes its whole factory (it writes every open idea in `~/Scriptorium/ideas`, maybe with paid models). Ask the user before `start scriptorium -Force`. VN Studio also starts Pixel Studio, Chiptune Studio and ComfyUI itself when a job needs them (VNO-11; it reads `services.json`, waits up to `startTimeout`, never starts Scriptorium, Strata, VibeTTS or LM Studio, and not ComfyUI while Strata answers). `hub.ps1 start` still works and shows a failure sooner. Turn it off with `enabled: false` in `~\VisualNovels\config\autostart.md` or `VNO_AUTOSTART=0`. A desktop app that holds the data folder makes the started copy exit; the job says why.
2. If an MCP tool is missing from your tool list, the server was down when the session started. Start it, then ask the user to reconnect it (`/mcp`) or restart the session. Until then call any tool through the hub: `pwsh -File scripts\hub.ps1 call <service> <tool> '<json args>'` (or `@args.json` for long arguments; it prints the JSON result). `hub.ps1 check` confirms each server answers.
3. Open a run log: `runs/<slug>.md` (copy `runs/_template.md`). Write every id you get (story slug, book slug, translator project id, VN project slug), each decision, and what you checked. A later session resumes from this file.
4. Agree with the user, briefly and only if they did not say: linear or with choices, for adults or children, language(s), art style (illustrated or pixel), voices on or off. Defaults: linear, adults, English, illustrated, voices off.
5. Agree who does the model work: the apps' own models (LM Studio, Strata or paid APIs), or **you**. See "Doing the model work yourself" below.

## Doing the model work yourself (no LM Studio, $0)

Scriptorium, VN Studio and Book Translator have a provider `client` with the model `client/claude-code`. A model request sent to it does not go to any model. It waits until you take it over MCP and answer it, then the app carries on as if a model had answered. Nothing is spent. It needs the branches SCP-08 / VNO-05 / BTT-09 (until merged), built and restarted.

**Setup, once per data folder.** Each app's `config/providers.md` needs the provider. The seed has it disabled, and existing data folders do not get it automatically:
```yaml
- id: client
  kind: client
  local: true
  concurrency: 8
  models:
    - id: claude-code
      vision: true
```

**Choose what you do, per book or project.** Never change the global role lists, or every book waits for you:
- Scriptorium:
  - `add_story {..., models: {writer: "client/claude-code"}}` sets the model from the start. Add `architect`, `editor-in-chief` and the reviewers if you do those too.
  - `set_book_model {book, role, model}` sets it on a running or rejected book. `model: null` removes it.
  - Roles: editor-in-chief, architect, writer, researcher, archivist, and the reviewers (continuity-checker, developmental-editor, line-editor, copy-editor, beta-reader, originality-checker, plus child-safety-reviewer, read-aloud-reviewer and fact-checker in some formats). The publisher makes no model call.
- VN Studio: `vno_update_settings {slug, models: {<role>: "client/claude-code"}}`. Roles: script-analyst, art-director, composer, stage-director, voice-director, edition-aligner, art-critic (it sends images), director. The Pixel Studio draw loop (`pixelProvider: pixel-studio-draw`) times out with `client`: draw sprites yourself with pixel-studio and `vno_asset_replace` instead.
- Book Translator: `create_project` or `update_project_settings` with `agentModels: {translator|glossary|proofreader|qa: ["client/claude-code"]}`. The CLI `translate` refuses such a project.

**The loop.** Run it until nothing waits.

| | Scriptorium | VN Studio | Book Translator |
|---|---|---|---|
| What waits | `list_client_tasks`, `factory_status.clientTasks` | `vno_client_tasks`, `vno_status`, `vno_wait` (returns when a task waits) | `list_client_tasks`, `wait_for_progress` (returns when a task waits) |
| Take one | `get_client_task {book?, role?, task?}` | `vno_get_task {…}` | `get_client_task {project?, role?, task?}` |
| Answer | `submit_client_task {taskId, text}` | `vno_submit_task {…}` | `submit_client_task {…}` |
| Give back | `release_client_task {taskId}` | `vno_release_task {…}` | `release_client_task {…}` |

- A task gives `system`, `user`, an optional `schema` and an `output` rule. Follow `output` exactly: one JSON object matching the schema; or the text only; or, in Book Translator, the `<seg id>` segments with every tag kept.
- A JSON answer is checked when you submit it. `accepted: false` comes with `problems`: fix them and submit again; the task stays yours.
- A task is held for you for 30 minutes, then goes back to waiting. "Task not found" means the job was stopped, answered or restarted: take the next one.
- Answer in the role's voice and to its brief. A writer's chapter must meet the word range in the prompt, and a reviewer must really review (honest scores and verdict), or the quality gate means nothing.
- Big runs: start several subagents, each taking tasks with its own `role` or `book` filter. Tasks are handed out one at a time, so two never get the same one.
- After the run, remove your model from the book or project (`set_book_model ... null`, or settings back), or later work on it waits for ever.

**A rejected Scriptorium book** gets another round with `reopen_book {book, mode: "rewrite" | "review", chapters?}`. That is different from `retry_book`, which is for `failed`. Set `set_book_model` first if you will write the rewrite.

## 1. Write the book (Scriptorium)

Two ways. Pick A unless the user wants it fast or Scriptorium is not available.

**A. Scriptorium writes it** (best quality, slow: tens of minutes to hours).
- `scriptorium.add_story` with `title`, `premise`, `plot`, `characters` [{name, role, description}], `setting`, `style`, and `format`: `visual-novel` (linear), `choice-visual-novel` (choices and several endings), `kids-visual-story` or `kids-choice-visual-story` (ages 6-9), or `kids-picture-book` (ages 3-6; see "Picture books" below). Put the looks of each character and place in `characters[].description` and `setting`: they become the art reference in the bible.
- Series: `add_series {title, premise, characters, setting, style, genre, format}` makes a series (file `~/Scriptorium/series/<slug>.md`); `add_story {..., series}` adds the next book (`series_index` is set automatically; a later book waits until the earlier one is published and gets the earlier books' summaries, cast end-states and open threads in its prompts); `list_series` / `get_series {series}` show the books in order. To let the user watch it write, start it with `pwsh -File scripts\hub.ps1 start scriptorium -Force -Window` (window open, MCP still on).
- **Adapt an existing book** (no new story needed): `adapt_book {book: <published book slug>, format: "visual-novel" | "choice-visual-novel", title?, notes?, models?}`, or the "Adapt to visual novel" button on a published book in Scriptorium's Library. The adaptation keeps the source's plot, cast and looks (the bible is seeded from the source), maps each script chapter to source chapters, skips research, and with choices keeps the book's ending as one canon path. Then go on to step 3 with the adaptation's book slug. Needs Scriptorium SCP-11 (merged after SCP-10).
- A VN script from Scriptorium (SCP-16) carries `CG:`, `INSERT:`, `SFX:` and `AMBIENCE:` lines (and `END CG`), and the bible gives each character an `Aliases:` sentence before `Voice:`. VN Studio reads all of them at import. Nothing fails a book for having no cue lines: look at how many it wrote (`get_script` lists them as `cue` beats).
- **The pack (SCP-45):** a published VN script also writes `vn/pack.json` (the fixed template: IDs, looks, scene and cue descriptions, puzzle logic) and `vn/text/<sourceLang>.json` (the only translatable text) into the book folder. Book Translator translates that catalog and VN Studio imports it; the chapter files stay the human authoring/review format. If an older book has no pack, call `build_vn_pack {book}` (or republish) and check the paths/hashes with `get_vn_pack {book}`. Never hand-edit `vn/pack.json`.
- **Mystery with puzzles** (format `mystery-puzzle-visual-novel`, Scriptorium SCP-18 and VN Studio VNO-15). Code makes every puzzle; Scriptorium only dresses it. Contract: Scriptorium's `docs/visual-novel.md`, "Puzzles".
  1. Choose the puzzles with the user: how many (2 or 3 in a short book), the kind of each (`murdle` now; `knights`, `testimony` and `grid` once VN Studio has them), and the band (`easy`, `medium`, `hard`).
  2. Make each core in VN Studio: `vno_puzzle_generate {band, seed?}` gives `{seed, core, names, text, difficulty}`. Keep the seed in the run log. Rename the items to the story's cast, weapons and places (`names`), and rewrite `text` to match; never change `core`.
  3. Write the brief: `add_story {..., format: "mystery-puzzle-visual-novel", puzzles: [{key, kind, title?, core, names, text, testimony?}]}`. Scriptorium keeps them as `bible/puzzles.md`, places each puzzle in a chapter, and its review checks that every clue is planted (`CLUE:`) before its `PUZZLE:` line.
  4. Wait for the book (`wait_for_book`, below). `get_script` lists `clue`, `evidence`, `puzzle` and `testimony` beats.
  5. Import it into VN Studio (step 3). The import reads `bible/puzzles.md` and the four lines, and runs the read-back check: a reader that sees only the prose must get back each clue's constraint. A failing clue is an import warning with its chapter: send it to Scriptorium as `add_book_note {book, chapter, text}` and `reopen_book {mode: "rewrite", chapters}`, then import again. Or fix the line in VN Studio with `vno_puzzle_set` and check it with `vno_puzzle_check_text`.
  6. Evidence pictures are `insert` images `cg_<key>`: plan and make them with the other art.
  7. Build, lint, and the user plays every puzzle, with at least one wrong answer.
- Every chapter gets a **humanizer** pass after drafting (role `humanizer`, on by default; `add_story {humanize: false}` turns it off for one book). Set it to `client/claude-code` with `models: {humanizer: ...}` if you do that work yourself.
- Scriptorium also writes **newspaper articles** (formats `article` / `feature-article`, topics in the `## Newspaper` section, published as `out/article.html`; Newspaper tab; `list_articles`). Not part of the VN chain, but the same story/task loop.
- `list_stories {status: open}` first: other open ideas compete with yours (max 3 books in progress).
- Wait with `scriptorium.wait_for_book {slug: <story or book slug>, timeout_seconds?}` (1 to 900, default 60; give it a story slug and it waits until the book starts). It returns `{done, reason, stage, chaptersWritten, chaptersPlanned, words, clientTasks, folder, epub, ...}` when the book is `published` (`done: true`), `rejected` or `failed` (`done: true` with `reasons`; then `get_book`, `read_book_file notes`, and `retry_book` for failed or `reopen_book` for rejected), when a model request waits for you (`reason: "client-task"`: answer it, then call again), or on `reason: "timeout"` (just call again; a book takes minutes to hours). If you do the writing yourself (`add_story {models}`), work the task loop between calls instead of only waiting. When the MCP link is down, `pwsh -File scripts\wait-book.ps1 -Story <story-slug>` (run in the background) polls the same stages through the hub and ends with the book folder when it is published (exit 1 on failed or rejected).
- Steer while it writes with `add_book_note {book, text, chapter?}`. Rate the result with `rate_book`.

**B. You write it straight into VN Studio** (minutes, no Scriptorium, no book folder). Write the story as JSON and call `vn-studio.vno_create_project {book, lang?, settings?}`; it returns the project `slug`, and you skip `vno_import` in step 3. The JSON shape, the beat forms and the ids are in `C:\projects\Personal\visual-novels-orchestrator\docs\mcp-guide.md` ("Write the story yourself"). In short:
- `book`: `{title, slug?, genre?, coverBrief?, characters: [{key, name, looks}], places: [{key, name, looks}], chapters: [{title, choices?: [{text, to: <chapter n>}], ending?, scenes: [{place: <key>, time?, description?, beats}]}]}`. Pass `slug` when the title is not in Latin letters.
- Pictures and sounds: the story may list `images` and `sounds` that beats show and play (`vno_image_set`, `vno_sound_set`; guide: "Pictures and sounds").
- Beats: `{cast: ["mara", "tom"]}` (who is on screen from here on, at most three), `{speaker: "mara", expression: "happy", text}`, `{text}` (narration).
- Linear: no chapter has choices. With choices: every chapter has `choices` or is an ending (`ending` text). Chapters are numbered by position.
- The language is detected from the text (or pass `lang`, any code from `vno_languages`).
- Check it with `vno_get_story {slug}`, fix it with `vno_story_edit {slug, ops}` or the one-op tools (`vno_beat_add`, `vno_beat_update`, `vno_scene_update`, `vno_character_set`, `vno_chapter_update` ...). Ids never change: scenes `ch01.s02`, beats `ch01.s02.b003`.
- A book folder in the Scriptorium layout still works too (`runs/<slug>/book/` + `vno_import`): grammar in `C:\projects\Personal\scriptorium\docs\visual-novel.md`, example `...\visual-novels-orchestrator\tests\fixtures\books\soother\`. A published SCP-45 book also has `vn/pack.json`; that is what Book Translator translates (it does not read VN Studio projects). A hand-written script may use the same `CG:`, `INSERT:`, `SFX:`, `AMBIENCE:`, `END CG` lines and `Aliases:` in the bible. Put a cue right before the beat it goes with (a cue at a scene's end is dropped with a warning), and keep `ON SCREEN:` for characters only.

Either way, the bible is what keeps the visuals consistent: every character and place needs a full, fixed description (face, hair, clothes, colours; place layout and light). Use one name per character everywhere. Expressions in speaker brackets should be one of: neutral, happy, sad, angry, surprised, worried, scared, thinking (VN Studio maps others to these).

## Picture books (slikovnice)

A picture book is the simpler sibling of a visual novel: one page = one scene, one full illustration with the people drawn into it, one to three short sentences under it, page turns. No sprites, no text box over the picture, no name tags, no CG or insert cues. It uses the same pack, assets pipeline and HTML5 build.

1. **Book.** `add_story {format: "kids-picture-book", ...}` (ages 3-6, one chapter, 12-16 pages; put the page count and the theme in the premise and notes). Scriptorium writes the `SCENE:` line with what the picture shows, an `ON SCREEN:` line naming who is in the picture, and one to three narration lines (the words under the picture) — no speaker lines, no `CG:`/`INSERT:`/`SFX:`/`AMBIENCE:`, no `---`. Check with `get_script` and `get_vn_pack {book}`: the `scenes` are the pages, the catalogue `beats` are the page texts. To write it yourself instead, use `vno_create_project` with `format: "kids-picture-book"` (or `presentation: "picture-book"`) and one scene per page.
2. **Import.** `vno_import {source}` reads the pack; the project gets `presentation: "picture-book"` and one page asset per scene (`bg_ch01_s01`, ...). The asset plan has no sprites and no CGs; `sheet_<char>` stay as internal references for likeness and are never shown in the book.
3. **Settings and art.** As for a visual novel: `art: {provider: "flow"}` (free, about 50 s a page) or ComfyUI, `music`, `voice: {enabled: true}` (the narration reads each page in order when clips exist), `sound: {sfxEngine: "none"}` unless a page really needs a bell or a door. Review the page images: the scene's cast must appear in the picture, with no text or lettering in it; make a bad page again with `vno_asset_regen {id, prompt?, seed?}`. A page with two or more children follows the VNO-34 rule (each named with looks and a side); a model can still merge them.
4. **Build, lint, play.** `vno_build` and `vno_lint` (a page with no image is an error, a page with no text a warning). Open `game/index.html`: click/tap or the arrow keys turn the pages, the language switcher changes the caption, and the menu's Load resumes the last page (the player quick-saves each page turn).
5. **Translate.** Exactly as a visual novel: translate the pack catalog with Book Translator and `vno_add_edition` (a hand-written catalogue file works too, as in `runs/the-bell-and-the-bicycle/vn-text-hr.json`); the illustrations are shared by every edition.
6. **A PDF is not an input.** A downloaded children's book (for example a Peppa Pig PDF) is a look reference only: never paste its text, characters or artwork into a production. Write an original story.

## 2. Translate (optional)

- **The reader book** (EPUB): `book-translator.create_project {sourcePath: <abs path to books/<slug>/out/<slug>.epub>, targetLanguage}` (add `clientOnly: true` when you do all the model work yourself: glossary, translator, proofreader and QA then go only to `client/claude-code`, nothing outside; needs BTT-10), then `start_translation`, then loop `wait_for_progress` until `done`, then `export_project` (returns the absolute output path). Any of its 32 languages.
- **A story written straight into VN Studio (1B JSON)**: translate the text yourself and write it with `vno_edition_set {slug, lang, title, chapterTitles: {"1": ...}, choiceTexts: {"1:0": ...}, endings: {"2": ...}, characterNames: {key: ...}, beats: {<beat id>: text}}` (the ids come from `vno_get_story`; the result lists what is still missing).
- **The visual novel edition** (VN Studio takes the languages in `vno_languages`): give Book Translator the **book folder** (`~/Scriptorium/books/<slug>` or `runs/<slug>/book/`), never a single `.md` file. With SCP-45 the folder has `vn/pack.json`; if it does not, call `scriptorium.build_vn_pack {book}` first.
  1. `book-translator.analyze_file {sourcePath: <abs book folder>, targetLanguage}`: `file.format` must be `vnp` (the pack adapter). If it says `vn`, the running Book Translator is older than BTT-23 (`hub.ps1 build book-translator`) or the book has no pack. Check the cost estimate.
  2. `create_project {sourcePath, targetLanguage}`, `start_translation`, loop `wait_for_progress` until `done`, then `export_project {projectId, outPath: <abs runs/<slug>/edition-<lang>>}`. It writes `<slug>.<lang>/edition.json`, a byte-identical `vn/pack.json`, and `vn/text/<lang>.json`. Only catalog values are translated: title/blurb, chapter and scene titles, choices, endings, character/alias display names, line/narration text, puzzle names and clue prose. The template, IDs, looks, cue descriptions, puzzle logic and UI are never in the translation.
  3. To translate it yourself instead (no app models, nothing spent): `create_project` with `enabledAgents: {glossary: false, proofreader: false, qa: false}`, `prepare_chunks`, then loop `get_translation_task` / `submit_translation`. Each segment is a catalog key; translate its value only, keep the segment shape, and keep names the glossary pins.
  4. `vno_add_edition {slug, source: <the bundle folder or the catalog JSON>, lang}`. It validates the pack hash against every key; expect `missing: []`, `extra: []`, `warnings: []`. `vno_sync_editions {slug, source: <book folder>}` adds every `vn/text/*.json` catalog at once. Fix single lines with `vno_update_beat`.
  - **The UI is VN Studio's, not the book's**: menus, Skip, Auto, Settings, Save/Load and puzzle labels come from `ui-strings.ts` (English source, Croatian table). Adding a language never translates the interface from the book; a language without a table falls back to English.
  - **Do not translate the EPUB as the game edition.** The EPUB is a reader artifact and its labels (`Narration:`, `On screen:`) are prose there. The game edition is the pack catalog.

## 3. Make the visual novel (VN Studio)

1. `vno_import {source}`: the Scriptorium book slug (it reads `~/Scriptorium/books`; `vno_set_library {path}` points it elsewhere) or the absolute path of a book folder. Returns the project `slug`. Skip this for a project made with `vno_create_project` (1B). With a pack, the import reads `vn/pack.json` + the source catalog directly and does not re-parse the chapters; `get_project` shows `packHash`, and `vn/text/*.json` catalogs can be added on import or with `vno_sync_editions`. Check the preview and `vno_get_story`: `images` and `sounds` are listed, no "dropped" cue warnings, aliases sit on their characters. A CG gets the bible characters named in its cue text as `characters` (VNO-16, at most 3); change them with `vno_image_set`.
2. `vno_update_settings {slug, ...}` before generating:
   - **Images come from Google Flow by default** (user, 2026-10-23): `art: {provider: "flow"}` with `style: "illustrated"` or `style: "pixel"` (Flow image, then the usual pixel finishing). Free (every call passes `max_credits: 0`), about 50 s an image against about 6 min for a ComfyUI CG, one Flow job at a time; a 70-image book takes about an hour. Start `hub.ps1 start flow-music-mcp` and check `flow_status` (signed in) first; if Flow's Chrome is not open yet, VN Studio opens it on the first call (VNO-22). Set the provider before the first image: switching mid-book mixes two looks, so then regenerate every image with the new provider.
   - Use ComfyUI (`art: {provider: null}`, qwen-image-2.1) only when the user asks, when Flow is down or signed out, or when a Flow video production holds the Flow queue; it can run in parallel with a Flow book. `art: {style: "pixel", pixelProvider: "pixel-studio"}` is pixel art through Pixel Studio (`pixel: {width, height}` default 320x180).
   - `music: {provider: "comfy"}` (ACE-Step, orchestral or any genre) or `music: {provider: "chiptune", chip: "nes"|"gb"|"genesis"|"snes"|"pce"|"ps1"|"dreamcast"}` (Chiptune Studio, the default for pixel books). `tracks` sets how many.
     - The sample chips (MDI-10, VNO-51): `ps1` (PlayStation SPU, hardware reverb) for late-90s, moody, noir, gothic or melancholy books; `dreamcast` (AICA, reverb/chorus/delay DSP) for lush, neon, dreamy, retro-futuristic ones. With no chip set, VN Studio picks `dreamcast` for a synthwave/neon/80s genre and `ps1` for a 90s/PlayStation one; everything else keeps the old choice (palette, else `snes`).
     - Synth moods for 80s / neon / cyber / noir books: `dreamwave` (calmest, the usual pick under reading), `darkwave` (dark chapters), `synthwave` (driving), `outrun` (only a chase or a climax). They sound best on `ps1` / `dreamcast`; the calm moods stay the default for every other book.
   - `voice: {enabled: true}` only if wanted; then `vno_voice_status`, `vno_voice_plan`, and the user may pick voices with `vno_voice_set`.
   - `sound: {sfxEngine: "chiptune", ambienceEngine: "chiptune"}` (VNO-19): Chiptune Studio makes the sound effects (picked by name from the key and description: coin, door, footstep ...; no match gives `blip` with a warning) and seamless ambience loops. Without `sfxEngine` a sound effect needs a file (`vno_asset_import`) and is skipped in the build with a warning until it has one; ambience then uses the music engine.
   - Google Flow as provider (VNO-10, FMM-11): `art: {provider: "flow"}`, `voice: {enabled: true, provider: "flow", langs: [...]}`, `music: {provider: "flow"}`. Needs `hub.ps1 start flow-music-mcp` (signed in; VN Studio reaches it on 7462, `flowUrl` in `config/studios.md` or `VNO_FLOW_URL`); check the `flow` entry of `vno_studios_status` first. Auto-start does not cover it. Images and Gemini voices are free (a small book takes about 20 to 30 minutes of images; Gemini's free tier allows only 10 voice clips a day). **Voice allocation rule**: if lines for a language exceed remaining free quota, use local VibeTTS. Always prefer Croatian on Google Voice over English. If both languages together exceed the free tier on that day, generate only Croatian on Google Voice and use local VibeTTS for English. **Music spends Flow Music credits**: ask the user first, at most `flowMusicMaxSongs` (4) songs, and each music job runs once. Details in VN Studio's `docs/mcp-guide.md`.
   - `theme`: see `vno_themes`.
   - To steer the art and music before anything is generated: `vno_plan {slug, wait: true}` writes the prompts only; then `vno_asset_set {slug, id, prompt}` for any you want to write yourself (kept by later runs), `vno_set_music {slug, menu, chapters: {"1": "music_02"}}` and `vno_set_cues {slug, scenes, casts}` (transitions, who stands left/center/right).
3. `vno_run_pipeline {slug}` (returns job ids at once), then `vno_wait {slug, timeoutSeconds: 240}` in a loop (Claude Code aborts an MCP call that is silent for 300 s, so stay under it), reporting `vno_status` progress to the user. Steps: analyse, art, music, generate, voice, stage, build, lint. Restart from any step with `from`.
4. Review: `vno_asset_list {slug}`. Look at the image files (Read them) for the character sheets (`sheet_<char>`) and the cover first, then sprites and backgrounds. In a picture book there are no sprites or CGs: review the page images, one per scene (`bg_ch01_s01`, ...), with the cast drawn in and no text in the picture; the sheets are only references there. Fix with `vno_asset_regen {id, prompt?, seed?}`, pick an earlier version with `vno_asset_pick`, and `vno_asset_lock` the good ones so a re-run keeps them.
5. Your own assets: make them anywhere and `vno_asset_replace {slug, id, file}` (absolute path, no post-processing: sprites must be transparent PNG/WebP about 972 px tall; backgrounds 1920x1080).
   - Pixel Studio: `import_image {path, palette, maxColors}` on a ComfyUI render, then `export_png {path, width, height}`.
   - Chiptune Studio: `compose_track {mood, chip, bpm, key, bars, seed}` then `render_audio {path, format: "ogg"}` (loops exactly; VN Studio plays the loop). Use one chip, key and instrument set for the whole book, and `save_as_asset` + `place_asset` for a recurring theme. On `ps1` / `dreamcast`, `new_song {chipConfig: {reverb: {preset: "hall"}}}` (PS1) or `{dsp: {preset: "chorus-hall"}}` (Dreamcast) sets the room; keep the default 16 voices. `compose_sfx` stingers and ambience work on both chips too.
   - VibeTTS: `synthesize_to_file {text, voice, lang, format}` for extra clips (Kokoro `af_*`/`am_*` English only; `supertonic:F1`-`M5` any language).
   - comfy-mcp (ComfyUI directly): `generate_image {prompt, engine, width, height, out}` for CGs and extra art, `edit_image {prompt, image, out}` to change an existing sprite or CG while keeping the subject, `remove_background {image, out}` for a transparent sprite, `generate_music {tags, engine, seconds, out}`, `generate_speech {text, language, voice_ref, out}`. Pass absolute `out` paths. A call returns the paths, or a job id after its `wait` seconds (default 45); then `wait {job_ids}`.
   - Google Flow and Flow Music are both in **flow-music-mcp** (`hub.ps1 start flow-music-mcp`; one Chrome profile, signed in once with `yarn login` in its repo). flow-mcp is retired.
   - Google Flow (`flow_*`): call `flow_status` first (sign-in, credits, the playbook). Free Nano Banana images for backgrounds, character sheets, CGs and covers: `flow_agent_images {scenes, out}` for a set, `flow_generate` for single shots; `flow_download` for 2K/4K. Then comfy-mcp `remove_background` for sprites. Video, video edits and Flow voices spend credits: ask the user first and pass `max_credits`. Free voices: `flow_narrate` with engine `gemini` (Google AI Studio key: `GEMINI_API_KEY` in flow-music-mcp's `.env`) or `windows`. Local and free: `flow_assemble` (clips + music + voice-over), `flow_transcribe` and `flow_captions` (whisper.cpp installs itself on first use; `flow_speech_setup` shows it).
   - Google Flow Music (`music_*`): `music_generate {sound, lyrics | instrumental: true, title, bpm?, length?, seed?, format: "wav", out}` makes one take in about a minute (48 kHz stereo; WAV about 35 MB for 3 min). Convert to ogg if VN Studio needs it, and `vno_asset_replace` it as a `music_0n`. It **spends Flow Music credits**: ask the user before the first one. `music_status` says if the profile is signed in (`yarn login` in the repo once). Verified end to end 2026-10-22 (instrumental, MP3 and WAV); lyrics, Advanced and Model are not tried yet.
   - **Pixel art with no ComfyUI** (every VN Studio image mode otherwise starts from a ComfyUI render): set `art: {style: "pixel", provider: "hand"}` (VNO-07; on an older engine, replace every image before the pipeline reaches `generate`). Write each image as a Python script with `scripts\pxcanvas.py`: a `Canvas` with shapes, dithered gradients, polygons, hand-written rows and outlines; `Studio().image(...)` / `.sprite(...)` paint it into Pixel Studio as `draw_grid` tiles and export through Pixel Studio, under a lock so several agents can draw at once. Grid 240x135 exported 8x (1920x1080). Sprites: 120 rows (960 px), transparent, bottom-aligned, faces in the top 70 rows (the text box covers the rest). Cover: also 240x135, it becomes the main menu. Example production with a style brief, reference scripts and parallel agents: `runs/the-soother-that-fell-into-dragon-land/art/` (`STYLE.md`). Agents check their work by reading the exported PNG, not `render_preview` (Pixel Studio has one current document for all clients).
   - Music by hand in Chiptune Studio (`new_song`, `write_melody` per channel with `wrap`, `write_drums`, `analyze_song`, `render_audio {loops: 2}`), then `vno_asset_replace` for each `music_0n` and `vno_set_music` for the chapter plan. Keep the `.ctune` projects next to the run.
   - **Puzzles**: a story can stop for a logic puzzle (a Murdle: who, with what, where) with a `puzzle` beat. Code makes and proves the puzzle (`vno_puzzle_generate`, `vno_puzzle_set`, `vno_puzzle_get`, `vno_puzzle_check_text`, `vno_puzzle_remove`); a model writes only the flavour. Do not write the logic yourself. Details and the order of steps: VN Studio's `docs/mcp-guide.md`, "Puzzles".
6. `vno_build {slug}` then `vno_lint {slug}`. The build lists any placeholder assets left and writes the self-contained HTML5 player (`game/game/index.html`, with `game/index.html` as a redirect). Since VNO-40 there is no Ren'Py or Android build step.
7. Play. The build is an HTML5 web player (VNO-40 replaced Ren'Py). Open the redirect in the user's browser: `Start-Process "$env:USERPROFILE\VisualNovels\projects\<slug>\game\index.html"` (or give the user the full path to `game\game\index.html`). The title screen shows the book; the top-right language switcher changes the text and the UI together. A picture book turns pages on click/tap and the arrow keys, one illustration with the text below, and the menu's Load resumes the last page. Only the user can say it plays well; ask them, and write the answer in the run log.

## 4. Finish

- Update `runs/<slug>.md`: what was made, where the files are, what was checked, what is left.
- Any tool limit you hit that a code change would fix: add it to that tool's own `ROADMAP.md` (in its repo, listed in the hub's `ROADMAP.md`), with the symptom. If the fix needs two or more tools, add it to the hub's `ROADMAP.md` as a new `HUB-NN` task instead.

## Things that go wrong

- MCP connection refused: the service is down. `hub.ps1 start <id>`, then `hub.ps1 logs <id>` if it does not come up.
- `unknown tool "vno_create_project"` (or another story tool): the running VN Studio is older than VNO-04. `hub.ps1 build vn-studio`, `hub.ps1 stop vn-studio`, `hub.ps1 start vn-studio`, then reconnect it.
- `hub.ps1 call` gives up after 15 s: call `vno_build`, `vno_lint` and other long tools with `wait: false`, then poll `vno_wait {slug, timeoutSeconds: 10}`.
- "engine.lock": another engine (the desktop app or an earlier headless start) already uses that data folder. Use the running one; its MCP is the same port.
- Scriptorium or Book Translator jobs fail with model errors: no model answered. Start LM Studio (`hub.ps1 start lmstudio`) or Strata (`hub.ps1 start strata`), then `scriptorium.check_servers`.
- ComfyUI out of memory: `vno_comfy_free` (or comfy-mcp `free_memory`), and do not run Strata at the same time as image generation.
- Pixel Studio and Chiptune Studio keep one shared document/song for every client: call them one at a time, never in parallel.
- `analyze_file` reports `vn`, not `vnp`: the running Book Translator is older than BTT-23 (`hub.ps1 build book-translator`), or the book has no pack (`scriptorium.build_vn_pack {book}`).
- `vno_add_edition` says the pack hash or a key does not match: the book was rewritten after the pack was made, or the catalog keys were renamed. Recompile the pack and start a new Book Translator project; do not force old text onto new IDs.
- A language shows some English lines: the edition is missing those beat keys. `get_project`/the build warning names them; `vno_update_beat` (or re-export the catalog) fills them.
- `unknown tool "build_vn_pack"`: the running Scriptorium is older than SCP-45. `hub.ps1 build scriptorium`, restart it, then call again.
